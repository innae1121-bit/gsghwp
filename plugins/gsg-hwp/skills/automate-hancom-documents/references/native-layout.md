# Rebuild a reference as native HWP content

This is the structure path: the user wants boxes, connectors, grids, grouped content, or a form in a screenshot, PPT export, or reference PDF turned into editable HWP content. Reading a value from an image and typing it into an existing document is a different job; read that value directly and call the matching write.

Treat the source as visual evidence, not as a page-sized image to paste. The model is the authority for visible text, semantic hierarchy, ownership, repeated-item count, color-to-label correspondence, proportions, and placement.

This guidance is also exposed verbatim as the UTF-8 MCP resource `gsg-hwp-beta://reference/native-layout`.

1. Call `hwp_analyze_reference_image` once with `full_scan=true`. This restores the complete evidence-first path: detected objects, text, lines, breakpoints, tiles, contact sheets, and the evidence overlay must exist before crop coordinates are finalized.
2. Read the source and returned overlay; use a contact sheet or detail crop only where that leaves meaning or ownership unclear. The model decides which elements are independent paragraphs, ordinary tables, editable graphic cells, captions, and separate raster assets; pixel analysis supplies boundary evidence and never decides meaning.
3. Keep photos, maps, drawings, logos, and graphic motifs as individual crops when their pixels are part of the content. Call `hwp_prepare_image_crops` once with every model-chosen semantic rough box. Choose `boundary_mode="tight_raster"` for one rectangular photo or continuous raster panel; its texture boundary must exclude adjacent title pills, body boxes, borders, and neighboring images. Choose `boundary_mode="annotated_group"` for a map, drawing, logo, or motif whose detached labels, callouts, or legend belong to that asset, and loosely include that complete group. Never guess a tight pixel crop or cut through owned visible text. The crop analyzer resolves the final boundary and returns both boxes, confidence, review state, individual PNGs, and a requested-versus-refined overlay.
4. Check crop contents and boundaries in the returned overlay; open individual crop files only where the grouped view leaves a boundary or owned detail unclear. If one item reports `needs_review=true`, use the analysis artifacts to adjust only that rough box once. Each raster block or cell must point to its matching refined crop, never to repeated copies of the full reference page.
5. Preserve every distinct visible relationship in the LayoutPlan, recursively at every nesting level. One visibly distinct fill/border surface owns one native cell or merged region. A group title band, repeated-item subheading pill, and each body box must be separate rows or cells even when adjacent; do not flatten them into differently formatted paragraphs or line breaks in one cell. For the common repeated item shown as one image beside a subheading over body text, build a two-row group: the image cell spans both rows, the right subheading owns the first row, and the right body owns the second row. Additional visibly separate body boxes require additional rows. Before preflight, compare the source's visible text surfaces with the planned non-image cells inside every repeated item; fewer planned cells means the plan is structurally incomplete. Do not combine a heading with its body, a label with an unrelated item, or independently colored/repeated items merely to reduce the row, cell, or image count. When the user asks to reorganize content for HWP, adapt the arrangement to the target page: repeated groups may wrap or stack, and their images, headings, and bodies may change size and placement together. Preserve content, relationships, ownership, and editability. Preserve source row/column geometry only when the user explicitly asks for exact replication. Choose dimensions and pagination from the actual content and target page, without fixed image sizes, row counts, page counts, or minimum font/margin thresholds.
6. Use paragraph/table/image blocks for independent content. Use a reference-layout block only when a coherent orthogonal grid, partial connectors, repeated style regions, or grid-fixed text dominate the page. The choice is semantic and geometric, not a fixed row or column threshold.
7. Analysis never overrides model-observed meaning. If `omissions` names an axis, the missing entries are unknown, not absent; never shrink the model's text, groups, colors, cells, or images to match the compact sample. Page only one necessary detail section through `hwp_get_reference_image_analysis_section`.
8. Hancom OCR is also optional evidence. Use it only for text too small, dense, or rotated to read reliably; it may fill a text-anchor gap but never overwrite model text or invent structure.
9. When page distribution or remaining space needs a planning decision, call `hwp_preflight_layout` once on the completed whole plan, including all pages. Do not probe the input shape with repeated small-table preflights; use the input example below. A settled plan can go directly to the batch write, which already runs the same preflight internally. Correct a `definite` overflow before mutation; handle a `possible` result with its explicit geometry choices instead of arbitrary shrinking. Use the page and block size observations in the `estimate_basis` entry prefixed `layout_observations=` to decide whether to rebalance widths, image sizes, spacing, grouping, or page breaks. These observations are not a design score or an additional approval gate. The pages are explicit plan segments numbered from the supplied starting page, not predicted physical pages; leading, consecutive, and final page breaks retain empty segments. Remaining height uses the starting page's usable area and subtracts the estimate; its lower bound also subtracts the existing one-sided uncertainty. A negative value describes excess height. The final segment separately reports the existing trailing-paragraph uncertainty, even after a final break; remaining height is estimated free body space, not the document's bottom margin or a required whitespace target.
10. Execute the declared plan with one `hwp_insert_layout` call at `target=current` or `target=after_page`, or one `hwp_append_layout` call only at the document end. The ordinary path compiles one protocol-9 `ApplyLayout` batch and the reference-grid path one protocol-10 `ReferenceLayoutBulk` command; never expand either into one call per cell, and never insert the full page first to delete, reinsert, move, or crop pictures afterward.
11. Derive breakpoints from visible box edges, text anchors, and connector endpoints. Start from absent borders, declare only visible outlines/connectors, use fill only for visible color surfaces, and never represent a connector as a filled spacer cell. Do not merge across a connector endpoint. Pass `source_image` on the reference-layout block, plus the `analysis_id` from step 1: with them the grid is placed at the source's own aspect ratio instead of being stretched to the body box, and the declared breakpoints snap to measured pixel edges.
12. Rebuild headings, body text, bullets, labels, captions, legends, and tables as editable paragraphs and cells. Reuse the target document's styles where available instead of imitating fonts blindly. Use the existing automatic document conventions; an optional one-time style read can resolve a specific unknown, but do not add a mandatory style scan or repeat an available read.
13. Inspect the created dimensions, cells, merges, fills, text, and image count, then render only the changed page with `hwp_render_page` (`CreatePageImage`). In that same render, compare positive features, ownership relationships, and crop contents against the source body. Judge whether each photo's subject remains identifiable, text has unnatural short lines, or spacing leaves unnecessary empty areas, in the context of the user's requested reorganization. If a write reports partial mutation or reconciliation required, stop instead of continuing or saving.
14. Correct only the affected dimensions, grouping, text fit, or spacing using the matching local edit. For reference-grid boundaries, text fit, padding, font, or border details, send `reference_layout_patch` against the existing `target_control_id` and render again. Do not delete and rebuild the page for a local defect.

Use `hwp_insert_layout` with `target=after_page` and `page=N` when the rebuilt page belongs after an existing page. It already isolates that page; do not add a second `page_break` block. Keep `auto_fit_row_heights=false` when the reference provides deliberate vertical geometry.

When two adjacent cells explicitly request different styles for the same shared border, keep the merge and cell structure and omit only those contradictory shared-edge overrides. The current document's table style then supplies that edge; unrelated outer borders and cell formatting remain explicit.

That conflict-inheritance rule applies to ordinary tables (`border_mode="inherit"`). Reference-layout grids use `border_mode="explicit"`: a visible edge wins over an omitted or explicit no-border neighbor and is mirrored to the other side, while all remaining edges are cleared. If two visible styles conflict, the upper or left cell's edge is canonical; avoid such ambiguity by declaring each source edge once.

Do not invent a figure caption, table title, group, or relationship that is absent from the source or the target form.


## Ordinary table and image input

The same `layout` value is accepted by insert, append, and preflight. Every block requires `kind`. Table `rows` is a rectangular array of cell objects: use `{"text":"..."}`, not a string, and `{}` for an empty cell. Declare merges in the table's `merges`, not on cells: `row`/`column` are zero-based and `row_span`/`column_span` default to 1. Keep covered cells empty. Cell pictures use `image_path`, `image_width_mm`, and `image_height_mm`; standalone image blocks use `path`, `width_mm`, and `height_mm`. Table `column_widths_mm` and `row_heights_mm` contain one dimension per column/row. Replace example paths with prepared individual assets and choose dimensions for the actual document and content.

```json
{"blocks":[{"kind":"table","rows":[[{"text":"제목"},{}],[{"text":"설명"},{"image_path":"C:/assets/photo.png","image_width_mm":40,"image_height_mm":30}]],"column_widths_mm":[50,50],"row_heights_mm":[10,35],"merges":[{"row":0,"column":0,"column_span":2}]},{"kind":"image","path":"C:/assets/map.png","width_mm":80,"height_mm":60}]}
```
